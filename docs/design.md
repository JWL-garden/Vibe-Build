> 핵심 원칙 4가지
> 1. **화면 ↔ 계산 ↔ 데이터를 분리**한다 (AI에게 부분 수정을 시키기 쉬움)
> 2. **법규와 비용·시세 가정은 코드가 아니라 데이터(설정 파일)** 로 둔다 → "완화 적용", "단가 변경" = 숫자만 바꾸기
> 3. **Mock 먼저, API는 나중** → 7일 중 어느 날 멈춰도 발표는 가능
> 4. **보고서의 모든 숫자는 계산 엔진에서 한 번만 계산** → 요약 페이지와 본문 숫자가 절대 어긋나지 않게
> 5. **(v3) 건축물 숫자의 정답은 기준 엑셀** → 계산 엔진 결과를 엑셀 값과 자동 대조(Vitest)해서 다르면 실패시킨다

## 1. 전체 시스템 구조

### 1-1. 기술 스택

| 구분 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Next.js (App Router) + TypeScript** | React 기반 + 서버(API Route)가 내장 → 공공 API의 CORS/키 숨김 문제를 별도 서버 없이 해결 |
| 스타일 | Tailwind CSS | AI가 가장 잘 다루는 스타일 방식. 인쇄용 스타일(print:)도 지원 |
| 상태관리 | Zustand | 단계(step) 간 분석 결과 공유가 간단 |
| 3D | **React Three Fiber + drei** | 건물 매스(박스/압출) 표현에 충분, 이미지 캡처 가능 |
| 차트 | Recharts | 완화 전/후 비교, 10년 누적 수익, 민감도 차트 |
| 보고서 PDF | 브라우저 인쇄(window.print) + 인쇄용 CSS | 별도 라이브러리 없이 "PDF로 저장" 가능 |
| 지도(선택) | Kakao Map 또는 생략 | 시간이 남으면 추가 |
| 테스트 | Vitest | 계산 함수 검증용 |
| 배포 | Vercel | Next.js 원클릭 배포 |

## 5. 계산 모듈 구조

모든 계산은 `lib/calc/`의 순수 함수(입력 → 출력, 외부 접근 없음).

### 5-1. 용적률 모듈 `far.ts`

```
입력: siteArea, farGFA(용적률산정 연면적), zone, rules(시나리오 적용 후 effectiveRules)
  farLimit     = rules.farLimitByZone[zone]          ← (v3) 시나리오가 상한값 자체를 교체
                 BASE: 2종 200 / 3종 250
                 완화(B): 2종 250 / 3종 300
출력:
  currentFAR   = farGFA / siteArea × 100
  maxGFA       = siteArea × farLimit / 100           ← (v3) 반드시 완화 후 farLimit 사용 (×1.2 금지)
  remainingGFA = max(0, maxGFA − farGFA)
  remainingNetArea = remainingGFA × 전용률            ← (v3) 전용률 = 기준 엑셀 '전용률' 값
```
(건폐율도 같은 파일: buildingArea / siteArea × 100)

> (v3) 수식 변경 주의: 기존 `farLimit × farMultiplier` 형태가 남아 있으면 모두 제거한다. `maxGFA`, `remainingGFA`, `newFAR`, 보고서 2장 비교표, 부록 법규표가 모두 같은 `farLimitByZone` 값을 읽어야 한다.
> 검증값(기준 엑셀 '용적률완화_주차검토'): 104-48 → 200.07㎡ × 250% = **500.175㎡**, 110-19 → 373.1㎡ × 250% = **932.75㎡**.

### 5-2. 일조권 모듈 `sunlight.ts`

```
d < 1.5m         → 허용 높이 0
1.5m ≤ d < 5m    → 10m 까지
d ≥ 5m           → 2 × d
```
- `maxHeightAtDistance(d, rule)`, `maxBuildingHeight(northSetback, rule)`
- 상업·공업 등 → `applies = false`
- 1차: 수직증축 단순화 / 2차(P2): 계단식 셋백
- northSetback: Mock은 숫자, 실제는 turf.js로 폴리곤 계산

### 5-3a. (v3) 주차 모듈 `parking.ts`

```
입력: units[](호별 주용도·전용면적·시설면적, 기준 엑셀 '주차대수_세대별'), actualParking, rules.parking
1) 현재법정대수 = 기준 엑셀과 같은 방식으로 재계산
     주택(제5호) 세대기준: 세대별 0.5 / 0.8 / 1.0 합산
     비주택: 용도별(근생 134㎡당 1대, 단독 제4호 등) 소수점 첫째자리까지 절사 후 합산 (비고4)
     현재법정대수 = 주택 합 + 비주택 합
2) 기존여유대수 spare = actualParking − 현재법정대수            (소수 오차 1e-6 보정)
3) 여유대수 안에서 "추가 전용면적이 최대"가 되는 세대 조합 탐색
     세대 유형: S(전용 ≤30㎡, 0.5대) / M(30~60㎡, 0.8대) / L(>60㎡, 1.0대, 면적 상한 = 용적률 잔여 전용면적)
     조건: 0.5·nS + 0.8·nM + 1.0·nL ≤ spare
     목표: 추가전용 = min(30·nS + 60·nM + L면적·nL, remainingNetArea) 최대
           (세대당 전용이 rules.parking.minUnitNet(15㎡) 미만이 되는 조합은 제외)
           (동점이면 세대수 많은 쪽)
     예) spare 0.5 → S 1세대(30㎡) / 0.8 → M 1세대(60㎡) / 1.0 → L 1세대(잔여 전용 전부) 또는 S 2세대(60㎡) 중 큰 쪽
4) parkingGFA = 추가전용 / 전용률     ← 주차 기준으로 설치 가능한 최대 연면적
5) 주차 추가 확보 옵션: spare 로 0세대일 때
     needFor1 = 0.5 − spare (기준 엑셀 '필요추가주차_1세대'), 실제 확보 대수 = ceil(needFor1)
     → 확보 후 spare' 로 3)~4) 재계산한 값을 "주차 N대 추가 확보 시" 안으로 함께 출력
출력: requiredNow, spare, addUnits[{type, netArea}], addNetArea, parkingGFA,
      parkingOption{addSpaces, addUnits, parkingGFA} | null, 근거 문장
```

### 5-3b. (v3) 주택 한도 모듈 `housingLimit.ts`

```
입력: units[], floors(층별 용도), rules.housing
  housingType   = 다세대 | 다가구 | 다중주택 | 기타(미적용)
  housingFloors = 주택으로 쓰는 층 수 (excludePilotiFloor=true면 1층 필로티 제외)
  housingArea   = 주택 전유 + 주택 공용 면적 합 (기준 엑셀 '전유공용면적_2단계')
  floorLimit    = rules.housing.maxFloors[housingType]     BASE 다세대 4·다가구 3·다중 3 → C 다가구 4·다세대 5
  areaLimit     = rules.housing.maxArea[housingType]       BASE 660 이하 → C 다가구·다세대 1,000 미만
출력:

```

### 5-3c. (2026-10-08) 전체 재건축 모듈 `rebuild.ts`

기존 건물을 철거하고 같은 대지에 **ALL 규칙**으로 신축할 때의 최대 규모. 기준 엑셀 '빈땅_신축시나리오' 산식을 따른다 (T1·T2는 그 시트에 없어 엑셀 대조 대신 Vitest 손계산).

```
입력: site(대지면적·용도지역·연면적·세대수·주차), housingType(기존 유형, 주택 아니면 다세대), 건폐율(zoningTable),
      northSetbackM(siteInputs), rules(ALL)
1) 최대 건축면적 = 대지면적 × 건폐율 (= 신축 기준층 바닥면적, 확인 필요)
2) 연면적 = min(대지 × 용적률 상한, 최대 건축면적 × 주택 층수 한도, 주택 연면적 한도('미만'이면 −0.01))
     같으면 제한요인 우선순위: 용적률 → 주택 층수 → 주택 연면적
3) 주택 층수 = ceil(연면적 ÷ 최대 건축면적), 지상 층수 = 주택 층수 + 1(1층 필로티 주차, 프로젝트 가정), 높이 = 지상 층수 × 층고
4) 일조: 이격거리 입력 시 허용 높이로 주택 층수·연면적 축소(제한요인 sunlight), 미입력이면 "확인 필요"
5) 전용 합 = 연면적 × 0.8, 세대수 = 내림(전용 합 ÷ 15㎡) (다가구 19세대 상한)
6) 법정 주차 = max(세대기준, 주택법 기준) → 대지 안 확보 가능 여부는 "확인 필요"
7) 판정: 신축 연면적 > 기존 용적률산정 연면적 → possible, 같거나 작으면 check, 0이면 impossible
자산가치: 재건축 후 = 토지가액 + 신축 연면적 × 재조달단가 (기존 건물가치 제외, demolished=true)
```

### 5-3. 증축 산정 모듈 `expansion.ts` (v3 개정)

증축 면적을 **층수 기준이 아니라 "주차대수로 설치 가능한 최대 연면적" 기준**으로 정한 뒤, 다른 제한으로 깎는다.

```
1) parkingGFA  = parking.ts 결과 (주차 여유 기준 최대 연면적)
2) farGFA      = remainingGFA (완화 상한 적용, 5-1)
3) housingGFA  = housingLimit.areaGFA (주택 연면적 한도, 주택 증축일 때만)
4) addGFA      = min(1, 2, 3)  → 0 이하면 0
5) addFloors   = ceil(addGFA / 증축층 바닥면적)            (증축층 바닥면적 = 5-3d floorPlate.ts, 계산 보류면 증축 불가 — 제한요인 roof)
6) 높이 검토   newHeight = 현재높이 + addFloors × 층고 ≤ 일조 허용높이(sunlight.ts)  → 넘으면 addFloors·addGFA 축소
7) 층수 검토   (2026-10-07 변경) 현재 주택 층수 + addFloors 가 한도를 넘으면 한도에 맞는 층수까지 addFloors·addGFA 축소,
               한 층도 못 올리면 "주택 층수 한도 초과" → 신규 층 주택 불가(addGFA=0, 판정 "확인 필요").
               층수 검토를 일조 검토보다 먼저 해서 일조는 최종 층수로 판단
8) 제한요인    = 최소값을 만든 항목: parking | far | housingArea | housingFloors | sunlight | other
출력: addUnits, addNetArea, addGFA, addFloors, newTotalFloors, newHeight, newFAR,
      limitingFactor, parkingOption(주차 추가 확보 시 안), checks[](항목별 통과/불가/확인필요), 근거 문장
```

- 정북 이격거리처럼 기준 엑셀에 없는 값은 `lib/data/siteInputs.json` 에 수기 입력하고, 값이 없으면 일조 검토를 **"확인 필요"** 로 표시(숫자를 지어내지 않음).
- `types/index.ts`의 `LimitingFactor`를 `'parking' | 'far' | 'housingArea' | 'housingFloors' | 'sunlight' | 'other'`로 확장하고, `lib/calc/index.ts`의 `LIMIT_LABEL`도 함께 수정.

### 5-4. 사업비·수익성 모듈 `finance.ts`

```
입력: expansion 결과(addGFA, addFloors), building, owner, market, financeAssumptions,
      (2026-10-07) landPrices·landLots(대표+구성 필지), siteInputs.lots, financeDefaults.landValueRule·buildingValueRule

[0. 토지가액]  calcLandValue — 개별공시지가 기준(시세 아님), 시나리오와 무관
  구성필지 = siteInputs.lots ?? (외필지수 = 0 ? [대표필지] : 없음)
  구성필지가 모두 토지대장·공시지가에 있으면:
      토지가액 = Σ(필지 토지대장 면적 × 필지 공시지가)
      |Σ면적 − 건축물대장 대지면적| ≤ areaToleranceM2(1㎡) → basis = sum        "공시지가 기준"
                                       그 외               → basis = mismatch   "면적 확인 필요"
  아니면 (외필지 목록·면적 없음):
      토지가액 = 대표필지 공시지가 × 건축물대장 대지면적  → basis = estimated  "추정"
  공시지가·대지면적이 없으면 basis = none (계산 불가)
  표기: "개별공시지가 기준 (시세 아님) · {기준연도}년 {기준월}월 1일 기준 · {공시일} 공시" + basis 배지

[A. 사업비]
  공사비        = addGFA × 공사비단가 + 구조보강비 + 승강기·설비비
  설계·감리비   = 공사비 × 설계감리비율
  인허가·부담금 = 가정 금액

  공사중손실    = 현재 월임대료 × 영업손실비율 × 공사기간(개월)
  금융비용      = 대출액 × 금리 × (공사기간/12) × 0.5   (평균 대출잔액 단순 가정)
  소계 → 예비비 = 소계 × 예비비율
  총사업비      = 소계 + 예비비
  대출액        = 총사업비 × 대출비율 / 자기자본 = 총사업비 − 대출액
  (금융비용과 대출액은 서로 영향을 주므로: 금융비용 제외 소계로 대출액을 먼저 정하는 단순화 사용)

[B. 수익]
  임대가능면적    = addGFA × 전용(임대가능)비율
  연 임대수입     = 임대가능면적 × ㎡당 월임대료 × 12 × (1 − 공실률)
  보증금 운용수익 = 증가 보증금 × 전환이율 (선택)
  연 운영비       = 연 임대수입 × 운영비비율
  연 NOI 증가     = 연 임대수입 + 보증금 운용수익 − 연 운영비
  연 이자         = 대출액 × 금리

[C. 지표]

  투자회수기간(년)     = 총사업비 / 연 NOI 증가
  자산가치 증가        = 연 NOI 증가 / 시장환원율

  (P1) 10년 현금흐름: 연차별 NOI(임대료 상승률 반영) − 이자 → 누적, NPV(할인율), IRR(반복계산)
```

> **(2026-10-08) report-inventory 6장 결정으로 위 구조를 교체** — 아래가 현재 기준이다.
> - **수익 모델 = 임대**(보증금 + 월세 기본), **사업주체 = 대표 1인**(공동소유여도 구분하지 않음), 가정값 기준시점 = **최근 12개월**.
> - **가정값 레지스트리**: 값은 가정값 입력 엑셀 '가정값' 시트(키·항목·단위·보수·기준·낙관·등급·자료명·기관·기준일·URL·메모) → `lib/data/inputs/assumptions.json`. 항목 정의(단위·ROI 방향·필수 여부)는 `lib/rules/financeDefaults.ts ASSUMPTION_SPEC`. 수익 시나리오 보수/기준/낙관 = 각 행의 보수/기준/낙관 값 (배수 조정 폐지). 우선순위: 사용자 입력 > 입력 엑셀. 검사: `assumptions.test.ts`(키·단위·순서·범위·A/B 출처, 등급 D 금지).
> - **근거 등급 C**는 허용하되 보고서에 범위(보수~낙관)와 함께 출력한다.
> - **임대료**: 연립·다세대 전월세 실거래, 전용 0~30㎡ / 30~60㎡, 당산동6가(구간별 10건 미만이면 영등포구 포함), 최근 12개월, 보증금·월세·관리비 → 가정값 입력 엑셀 '임대사례' (고정값). `npm run data:rent`(서울 열린데이터광장 tbLnOpendataRentV, 키는 `.env.local SEOUL_OPEN_API_KEY`)로 한 번 받아 저장하거나 직접 입력 — 화면·계산은 API를 부르지 않는다. 구간별 중위값(`summarizeRentComps`).
> - **전월세 전환율**: 주택 법정 상한 = min(10%, 기준금리 + 2%p)(주택임대차보호법 시행령 제9조), 상가 = min(12%, 기준금리 × 4.5)(상가건물 임대차보호법 시행령 제5조). **보수 = 법정 상한, 기준·낙관 = 시장 전환율**. 주거 외 용도(사무실 등) 증축·신축분은 상가 기준(보수 = min(시장, 법정 상한)).
> - **공사비**: 증축 = **평당 800만원 + 세대당 인허가 등 제반비용 500만원**. 신축 = **max(한국부동산원 건물신축단가표, 엑셀 신축비용 자료)** 와 그 근거를 함께 표기.
> - 2026-10-08 입력값(출처): 기준금리 3.00%(한국은행 2026.8.27) · 시장 전환율 5.625%(서울주택정보마당 영등포구 연립다세대 2025 4분기~2026 3분기 평균) · 신축단가 2,055,379원/㎡(2025 건물신축단가표 다세대 용도별 평균, 2차 인용) · 취득세 등 3.16%(지방세법 원시취득) · 대출금리 4.66%(한국은행 2026.8 주담대 신규취급). 나머지(공실·운영비·예비비·환원율·공사기간·대출비율·상승률·할인율)는 등급 C 프로젝트 가정.
