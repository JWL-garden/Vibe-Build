규칙

docs/report-inventory.md 구성:

## 1. 보고서 숫자 추적표 (설계서 11장 0~10장 + 부록 기준)
장별로 보고서에 출력되는(또는 출력 예정인) 숫자를 한 행씩 적어줘.
| 장 | 항목 | 계산 함수(파일:함수) | 입력 데이터 | 입력 출처 | 구현 상태 | 테스트 | 근거 등급 |
- 입력 출처: 기준엑셀(시트명) / siteInputs 수기 / 법령·조례(조문) / 정책 보도자료 / 예시 가정값 / 하드코딩
- 구현 상태: 구현 / 부분 구현 / TODO / 화면에서 직접 계산(규칙 위반)
- 테스트: excelParity / 손계산 Vitest / 없음
- 근거 등급: A=공식 데이터·법령 / B=공개자료 기반 추정 / C=프로젝트 가정 / D=근거 없음(하드코딩·임의값)
T1(104-10), T2(110-19) 각각 현재 값이 나오면 함께 적어줘.

## 2. 계산 엔진 현황
lib/calc/ 모듈별: 함수 목록, 설계서 5장 대응 번호, 구현/TODO, 입력→출력 요약, 테스트 수.
특히 finance.ts는 [0]토지가액 [A]사업비 [B]수익 [C]지표 [C']자산가치 [C'']토지포함수익률 [D]비교 각각의 상태를,
sensitivity.ts·financeScenarios.ts·runAll의 analyzeFinance 연결 상태와 함께 적어줘.

## 3. 데이터 검증 방법 현황
지금 있는 검증 장치를 모두 정리해줘: data:check 검사 항목, excelParity 대조 항목·허용오차, Vitest 손계산 케이스,
data-changelog 절차, "샘플 데이터/예시 가정값" 표기 규칙.
그리고 "검증되지 않는 숫자" 목록(보고서에 나오는데 어떤 검증에도 걸리지 않는 값)을 따로 뽑아줘.

## 4. 추가로 필요한 데이터
아래 3그룹으로 나눠서 항목 | 쓰이는 계산 | 지금 상태 | 없으면 보고서에 생기는 문제 | 확보 방법 을 표로 정리해줘.
 (가) 내가 도면·대장·현장에서 제공할 수 있는 값
      예: siteInputs의 정북 이격거리·최상층 바닥면적·필로티 여부, T2 외필지 3개 PNU, T1 대지면적 불일치(대장 199.5 vs 토지대장 223㎡) 판단
 (나) 공공데이터·공개자료로 확보할 수 있는 값 (실거래가, 전월세, 공사비 지수 등)
 (다) 내가 제공할 수 없는 값 — 공사비·구조보강비·설계감리비·인허가 부담금·세금·임대료·공실률·환원율·금리·대출비율·운영비·공사중 손실 등
각 항목에 "보고서 필수 / 있으면 좋음"을 표시해.

## 5. (다) 그룹의 계산 엔진 구성안 — 코드 말고 설계만
내가 숫자를 줄 수 없는 항목을 "근거 있는 가정값"으로 계산하는 구조를 제안해줘.
 5-1. 항목별 산정 방식 표
      | 항목 | 산정식 | 근거 출처 후보(기관·자료명) | 갱신 주기 | 값 형태(단일/범위 low·base·high) | 근거 등급 | 보고서 표기 문구 |
      - 출처 후보는 기관·자료명만 적고, 실제 수치는 넣지 마 (확인 전 수치 금지).
      - 다가구·다세대 주택 증축이므로 임대료는 상가가 아니라 주택 전월세 기준인지, 전세↔월세 전환(전환율)을 어떻게 다룰지,
        다세대는 분양(매각) 모델도 가능한지 — "임대 모델 vs 분양 모델" 선택지를 비교해줘.
 5-2. 가정값 레지스트리 구조
      lib/rules/financeDefaults.ts를 "값 + 단위 + 범위 + 출처 + 기준일 + 근거 등급 + 메모"를 갖는 레지스트리로 바꾸는 타입 초안.
      우선순위(사용자 입력 > 필지별 시장데이터 > 기본 가정)와 각 값이 보고서 부록 가정값 표·출처 표로 자동 출력되는 흐름.
 5-3. 불확실성 처리
      보수/기준/낙관 시나리오와 민감도(토네이도)를 범위 값에서 자동 생성하는 방식,
      "근거 등급 C 이하 항목이 결론(ROI·회수기간)에 미치는 영향" 표시 방식.
 5-4. 검증 방법
      손계산 기준 케이스(T1·T2 각 1개), 합계 검산(사업비 항목 합 = 총사업비 등), 범위 이상값 검사를 data:check처럼 자동화하는 안.

## 6. 내가 결정해야 할 것
위 작업에 필요한 내 결정 사항을 질문 목록으로 정리해줘 (예: 수익 모델 임대/분양, 기준 시점, 근거 등급 C 허용 범위).
각 질문에 너의 추천안과 이유를 한 줄씩 달아.

## 7. 다음 작업 순서 제안
보고서 근거 완성까지 남은 작업을 우선순위(P0/P1/P2)와 의존관계로 정리하고, 각 작업에 붙여 넣을 Claude Code 명령을 1~3줄로 적어줘.
페이지·디자인 작업은 맨 마지막 "보류" 그룹에 이름만 적어.

작성이 끝나면 핵심만 10줄 이내로 요약해서 보여주고, 커밋은 내 확인 후에 해.
