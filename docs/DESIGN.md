# 설계 문서: 법규 완화에 따른 일조권·용적률 검토 및 건축물 증축 가능성 분석 웹서비스

BIM-IT 융합과정 최종 프로젝트 / 개발 기간 7일 / React 기반 프로토타입

> 사용자가 주소를 입력하면 "이 건물은 현재 조건에서 몇 층까지, 어느 정도 규모로 증축을 검토할 수 있는가?"를 직관적으로 보여준다.

## 핵심 원칙

1. **Mock(또는 전처리한 로컬 데이터)을 먼저 쓰고, 실제 API는 나중에 연결한다.** 발표 당일 API가 멈춰도 데모는 돌아가야 한다.
2. **계산 로직은 화면 코드와 분리한다.** 용적률·일조권 계산은 화면과 무관한 독립 함수로 만들고 따로 검증한다.
3. **완화 전과 완화 후는 같은 계산 함수에 다른 규칙값을 넣어 구한다.** 계산 코드를 두 벌 만들지 않는다.

## 2. 웹페이지 화면 구성

**레이아웃:** 상단에 진행 단계 표시(Stepper), 왼쪽 70%는 단계별 본문, 오른쪽 30%는 늘 보이는 요약 카드.

```
┌─────────────────────────────────────────────────────────────┐
│ ① 대상건물 ② 주변건물 ③ 일조권 ④ 용적률 ⑤ 완화 ⑥ 증축 ⑦ 3D ⑧ 결과 │
├───────────────────────────────────────────┬─────────────────┤
│                                           │ 📋 요약 카드      │
│        (단계별 본문 영역)                   │ 주소: …          │
│                                           │ 현재: 4층 / 180%  │
│                                           │ 완화 전: +2층     │
│                                           │ 완화 후: +4층     │
│            [이전]          [다음 →]        │                  │
└───────────────────────────────────────────┴─────────────────┘
```

| 화면 | 보여줄 내용 | 시각 요소 |
|---|---|---|
| 0. 주소 입력 | 검색창과 **예시 주소 버튼 3개**(발표용) | 큰 검색창 |
| 1. 대상 건축물 | 용도지역, 대지면적, 건축면적, 연면적, 층수, 높이, 구조, 준공년도 | 정보 카드, 미니 지도 |
| 2. 주변 건축물 | 주변 건물 목록(거리, 방위, 층수, 높이). **정북측 인접대지 강조** | 2D 배치도(SVG), 표 |
| 3. 일조권 | 정북방향 이격거리, 높이별 필요 이격거리, 일조권상 최대 높이 | **단면도 SVG**(건물과 사선) |
| 4. 용적률 | 현재 용적률 대비 법정 용적률, 잔여 연면적 | 막대·게이지 차트 |
| 5. 법규 완화 | 완화 시나리오 카드 선택과 슬라이더, 각 시나리오의 근거 | 토글 카드 |
| 6. 증축 규모 | 완화 전/후 비교표(층수, 연면적, 지배조건) | 비교표, 배지 |
| 7. 3D 시각화 | 기존 건물, 증축층, 주변 건물, 일조사선 | 3D 뷰어와 토글 |
| 8. 최종 결과 | "현재 4층 → 완화 후 최대 8층, +620㎡" 한 문장 결론과 검토 한계 | 결과 대시보드, 인쇄 버튼 |

## 5. 일조권·용적률 계산 모듈 구조

```
src/lib/calc/
├── types.ts          데이터 형태 정의 (Site, Building, Rules, Result)
├── zoningTable.ts    용도지역별 법정 기준표
├── far.ts            용적률 계산
├── sunlight.ts       일조권 사선 계산
├── relaxation.ts     완화 규칙 적용 (기본규칙 + 시나리오 → 최종규칙)
├── expansion.ts      종합: 층별 매스 생성 → 증축 층수·연면적
└── __tests__/        손계산 예제로 검증
```

### (1) 용적률 `far.ts`
- 현재 용적률 = 지상층 연면적(용적률산정연면적) ÷ 대지면적 × 100
- 허용 연면적 = 대지면적 × 허용 용적률
- 잔여 연면적 = 허용 연면적 − 현재 용적률산정연면적

### (2) 일조권 `sunlight.ts`
건축법 시행령 제86조에 따라 전용주거지역과 일반주거지역에서 정북방향 인접대지경계선으로부터 다음 거리를 띄워야 한다.
- 높이 **10m 이하** 부분은 **1.5m 이상**
- 높이 **10m 초과** 부분은 **해당 높이의 1/2 이상**

> ⚠ 2023년 개정으로 기준 높이가 9m에서 10m로 바뀌었다. 발표 전에 최신 조문을 확인할 것.

함수는 높이 h를 받아 필요 이격거리를 돌려준다. 규칙값은 매개변수로 받는다: `기준높이(10)`, `기준이하 이격(1.5)`, `초과부 비율(0.5)`.

**층별 후퇴(계단형 매스)**
- i층 상단 높이 = i × 층고
- 그 층의 필요 이격거리를 구한다.
- 건물 북측 외벽이 그 거리보다 경계에 가까우면 그만큼 북쪽을 깎아 바닥면적을 줄인다.
- 바닥면적이 최소값보다 작아지면 그 층부터는 증축할 수 없다.

결과적으로 위로 갈수록 북쪽이 계단처럼 깎인 형태가 나오고, 이 형태가 3D에서도 그대로 보인다.

### (3) 증축 산정 `expansion.ts`
```
입력: 대지, 기존건물, 최종규칙
1. 기존 층 위로 한 층씩 쌓아본다 (수직증축 가정, 기존 footprint 기준)
2. 매 층마다 확인:
   - 일조권: 이 층의 허용 바닥면적 (북측 후퇴 반영)
   - 높이제한: 최고높이 이하인가 (있다면)
   - 용적률: 누적 연면적이 허용 연면적을 넘지 않는가
3. 하나라도 걸리면 중단 → 그 조건이 "지배조건"
출력: 증축 층수, 층별 면적 목록, 추가 연면적, 최종 용적률, 지배조건
```

> 💡 이 함수를 **기본 규칙으로 한 번, 완화 규칙으로 한 번** 호출하면 완화 전/후 비교가 끝난다.

## 6. 법규 완화 조건 적용 방법

완화 조건을 코드 안에 쓰지 않고 **데이터(JSON)로 정의**한다.

```
기본 규칙 (용도지역 기준표에서 생성)
   +  선택한 완화 시나리오 (JSON의 변경값만)
   =  최종 규칙  → expansion 계산 함수에 투입
```

| 시나리오 | 변경 내용 | 바뀌는 규칙값 |
|---|---|---|
| A. 용적률 상한 완화 | 조례 용적률 대신 국토계획법 상한 적용 (예: 2종 200% → 250%) | `용적률` |
| B. 노후건축물 리모델링 특례 | 기존 연면적의 일정 비율(예: +30%)만큼 추가 허용 | `용적률 가산` |
| C. 일조사선 완화 | 기준높이 10m → 15m, 또는 초과부 비율 1/2 → 1/4 | `일조 기준높이`, `비율` |
| D. 복합 | A + C 동시 적용 | 여러 값 |

시나리오 하나는 이름, 설명, 근거(가정/실제 조문), 변경값(바꾸고 싶은 항목만)으로 구성한다.
`relaxation.ts`는 기본 규칙에 변경값을 덮어쓰는 일만 한다. 새 완화 조건을 추가할 때는 **JSON만 수정하면 된다.**
화면에는 반드시 **"프로젝트 가정"** 배지를 표시한다.

## 7. 3D 시각화 방법

React Three Fiber로 그린다 (1 유닛 = 1m).

| 요소 | 표현 | 색상 |
|---|---|---|
| 대지 | 바닥 평면 | 연녹색 |
| 기존 건물 | 층별 박스 | 회색 |
| 증축층(완화 전) | 층별 박스, 일조 후퇴 반영 | 파랑 반투명 |
| 증축층(완화 후) | 추가된 층 | 주황 반투명 |
| 주변 건물 | footprint 돌출(Extrude) | 연회색 |
| 일조 사선 | 기울어진 평면 | 빨강 반투명 |
| 방위 | 북쪽 화살표 | — |

- 마우스 회전·확대(OrbitControls)
- 토글: [완화 전 / 완화 후], [사선 보기], [주변 건물 보기]
- 층에 마우스를 올리면 "6층, 바닥면적 142㎡" 툴팁 표시
- (선택) 동지 기준 태양 위치 그림자 애니메이션
- 3D 컴포넌트는 계산 결과(층별 면적·높이 목록)만 받아서 그리고, 직접 계산하지 않는다.

## 8. Mock / 로컬 데이터로 먼저 구현할 부분

영등포구 원본 데이터에서 예시 대지 3곳을 골라 JSON으로 만든다. 결과가 서로 다르게 나오도록 고른다.

| 예시 | 특징 | 보여줄 포인트 |
|---|---|---|
| ① 일반주거지역, 저층 건물 | 정북측 거리가 짧음 | **일조권이 지배조건** |
| ② 일반주거지역, 저층 건물 | 북측이 넓게 열림 | **용적률이 지배조건** |
| ③ 준주거 또는 일반상업 | 일조권 미적용 | 비교용 대조군 |

```
src/data/
├── sites.json          예시 3곳 (주소, PNU, 대지 폴리곤, 건물, 용도지역)
├── neighbors.json      대지별 주변 건물
├── zoningTable.json    용도지역별 기준
└── scenarios.json      완화 시나리오 A~D
```

`getBuilding()` 같은 서비스 함수는 Mock이든 실제 API든 **같은 형태의 데이터**를 돌려줘야 한다. 그래야 데이터 출처를 바꿔도 화면 코드는 그대로 둘 수 있다.

## 9. 실제 API 연결이 필요한 부분

| 우선순위 | API | 제공처 | 얻는 데이터 | 난이도 |
|---|---|---|---|---|
| ⭐1 | 도로명주소 검색 | 행정안전부 juso.go.kr | 주소, 법정동코드, 번지 | 쉬움 |
| ⭐1 | 건축물대장 표제부 | 국토부(공공데이터포털) | 면적, 층수, 용적률, 높이 | 보통 |
| 2 | 주소→좌표 | 카카오 로컬 API / VWorld | 위경도 | 쉬움 |
| 3 | 토지이용계획(용도지역) | VWorld | 용도지역 | 보통 |
| 4 | 건물 형상(GIS 건물통합정보) | VWorld / 국토정보플랫폼 | footprint, 높이 | 어려움 |

- API 키 발급에 1~2일 걸릴 수 있으니 미리 신청한다.
- 공공데이터포털 API는 브라우저에서 직접 호출하면 CORS 오류가 나는 경우가 많다. 개발 중에는 Vite 프록시를, 배포 시에는 Vercel 서버리스 함수를 쓴다.
- API 키는 `.env`에만 두고 GitHub에 올리지 않는다.
- **현실적인 목표:** ⭐1번 두 개만 실제로 연결하고 나머지는 로컬 데이터를 유지한다. 실제 데이터에 없는 값(정북 이격거리 등)은 가정값 입력란으로 보완한다.

## 검토 범위와 한계 (발표 시 명시)
