## 0. 한 줄 콘셉트

**"건축주와 함께 검토하는, 투명한 증축 타당성 리포트"**

- 키워드: 신뢰 · 정밀 · 절제 · 큰 타이포 · 투명한 근거
- 방문자: 건물주(주 사용자), 건설사·건축사(검토자)
- 레퍼런스: **애플 코리아 메인 화면** — 흰색·옅은 회색 구획, 큰 제목, 짧은 설명, 파란 행동 요소, 여백이 큰 전폭 타일
- 따라 하는 것은 레이아웃·색·타이포·여백의 "방식"이다. **애플의 로고, 제품 이미지, 문구는 쓰지 않는다.**

### 디자인 원칙 3가지
1. **여백과 큰 타이포로 신뢰감을 만든다.** 장식은 줄이고 숫자와 문장이 주인공이다.
2. **파랑은 "건축주가 만지는 곳", 주황은 "증축분"에만 쓴다.** 입력·선택·버튼·링크가 파랑이고, 증축분(3D의 증축 층, 증축 후 값, 증축한 경우의 선)이 주황이다. 시스템이 계산한 결과 숫자는 잉크색·회색이다.
3. **모든 숫자에는 근거 표기가 붙는다.** "예시 가정값", "샘플 데이터", 법규 근거, 면책 문구를 숨기지 않는다.

## 1. 색상 팔레트

**페이지 바탕은 흰색과 옅은 회색(Mist)이다. 다크 모드와 큰 검은색 배경 섹션은 쓰지 않는다.**

| 역할 | 토큰 | HEX | 사용처 |
|---|---|---|---|
| 기본 글자·제목 | `ink` | `#1d1d1f` | 본문, 제목 |
| 보조 글자 | `ink-soft` | `#6e6e73` | 설명, 부제 |
| 흐린 글자 | `ink-faint` | `#86868b` | 캡션, 각주, 비활성 |
| 바탕 | `paper` / `mist` | `#ffffff` / `#f5f5f7` | 페이지 / 번갈아 쌓이는 구획 |
| 선·테두리 | `line` | `#d2d2d7` | 카드 테두리, 구분선 (헤더는 `line/60`) |
| 상호작용 | `action` | `#0071e3` | 주요 버튼, 선택된 카드·행의 테두리/배경(`action-soft #e8f1fc`), 포커스 |
| 상호작용(호버) | `action-hover` | `#0077ed` | 버튼 호버 |
| 텍스트 링크 | `link` | `#0066cc` | 본문 안 링크, "더 알아보기 >" |
| 증축분 | `accent` | `#e0621b` | 3D의 증축 층, 증축 후 값 강조, "증축함" 선. 건축주 입력 색이 아니다 |
| 기존 건물 | `existing` | `#8d9494` | 3D의 기존 건물, 비활성 도형 |
| 짙은 보조 | `deep` | `#424245` | 표 머리글, 배지(판정), 도면 선 |

**비율 가이드:** 흰색·Mist 80% / Ink 12% / action 5% / accent 3% (accent는 증축분이 있는 화면에서만)

**주의**
- 파랑 `#0071e3` 위의 흰 글자는 버튼 글자(굵게 17px)까지만 쓴다. 작은 본문 글자색으로는 `link #0066cc`를 쓴다.
- 주황은 입력·선택·링크·장 번호에 쓰지 않는다. (판정 배지·장 번호는 `deep`)
- 그라디언트와 네온 색은 쓰지 않는다. 구획은 `mist` 배경과 `line` 선으로 나눈다.

## 2. 폰트

> 애플 코리아의 실제 값은 텍스트만으로 확인하지 못했다. 아래는 공개된 일반적 특징에 기반한 제안값이다. 확인 방법은 7장.

| 용도 | 서체 | 비고 |
|---|---|---|
| 제목·본문·UI·숫자(전부) | `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", Pretendard, "Malgun Gothic", system-ui, sans-serif` | 애플 기기는 시스템 글꼴, 그 밖은 Pretendard 가변 폰트(`app/fonts`, OFL). SF Pro·Apple SD Gothic Neo 파일은 라이선스상 직접 배포하지 않는다 |
| 세리프 | 쓰지 않음 | `font-serif`는 산세리프와 같은 스택으로 연결(기존 코드 호환) |

### 크기·행간 (데스크톱 기준 / 모바일은 70~80%)
| 요소 | 크기 | 굵기 | 행간 | 자간 |
|---|---|---|---|---|
| 히어로 제목 (`text-display`) | 56px | 600 | 1.07 | −0.005em |
| 히어로 위 한 줄(소제목) | 24px | 600 | 1.2 | 기본 |
| 히어로 설명 | 21px | 400 | 1.38 | 기본 |
| 섹션 제목 (`text-h2`) | 40~48px | 600 | 1.1 | −0.003em |
| 타일 제목 (`text-h3`) | 28px | 600 | 1.15 | 기본 |
| 본문 (`text-body`) | 17px | 400 | 1.47 | −0.022em |
| 캡션·각주·면책 (`text-caption`) | 12px | 400 | 1.33 | 기본 |
| 핵심 숫자 (`text-kpi`) | 56px | 600, `tabular-nums` | 1.1 | −0.005em |

공통 규칙: 국문은 `word-break: keep-all`, 숫자는 `font-variant-numeric: tabular-nums`.

**보고서(A4) 주의:** 글꼴·크기를 바꾸면 쪽 나눔이 달라진다(`ReportPage`, `lib/report/paginate.ts`). 본문 10~10.5pt 기준을 유지하고, **디자인 확정 후 인쇄 미리보기로 쪽 나눔을 재검토**한다.

## 3. 이미지 스타일

- **자체 3D 매스 모델이 주 비주얼이다.** 기존 건물=회색, 증축분=주황, 일조 사선면=반투명, 주변 건물=흰색.
- 선은 가는 라인의 도면 느낌. 배경은 흰색 또는 Mist 단색. 그림자는 약하게.
- 사진을 쓴다면 흐린 날의 낮은 채도, 국내 도심 중소규모 건축물 입면. 라이선스가 확인된 것만 쓴다.
- 애플의 로고·제품 사진·문구, 스톡 악수/회의 사진, 만화적 캐릭터는 쓰지 않는다.
- 샘플 건물·주소·수치는 모두 가상 값이므로 **"샘플 데이터" 표기**를 붙인다. 가짜 후기·고객사·실적은 넣지 않는다.

## 4. 레이아웃 — 애플 코리아 메인 구조

> 애플 코리아 메인은 텍스트 구조 기준으로 확인했다(상단 메뉴 → 큰 소개 블록 여러 개 → 푸터). 시각적 세부(간격 등)는 직접 열어 확인하고 보정한다.

### 4-1. 메인 (`app/page.tsx`)

| 순서 | 구역 | 내용 |
|---|---|---|
| ① | 상단 바 | 높이 44px, 흰색 80% 투명 + 배경 블러, 왼쪽 서비스 이름만(메인에서는 주소 검색 버튼 없음) |
| ② | 히어로 (흰색 바탕) | 가운데 정렬: 소제목 → 큰 제목 → 한 줄 설명 → **주소 입력칸**(누르면 T1·T2 주소 목록) + [분석하기] 파란 버튼 |
| ③ | 타일 블록 | 전폭 섹션이 흰색 / Mist로 번갈아 쌓임. 블록마다 제목 + 한 줄 설명 + 링크 2개(더 알아보기 >, 샘플 보기 >). 내용: 법규 완화 검토 / 일조·용적률 분석 / 3D 증축 시뮬레이션 / 건축주 보고서 *(문구는 초안 확인 후 적용)* |
| ④ | 샘플 사례 | 반폭 타일 2개(T1·T2 요약, "샘플 데이터" 라벨) |
| ⑤ | 푸터 (Mist) | 각주 번호, 면책·데이터 출처·문의, 작은 글씨 |

간격: 섹션 상하 80~100px, 타일 사이 12px, 카드 모서리 18px(`--radius-card`), 콘텐츠 폭 1024px 안팎(주소 입력칸 680px).

### 4-2. 분석·보고서 화면
- 분석 화면: 설계서 2-2의 구성 유지. 색·폰트 토큰만 이 문서를 따른다. 선택 요소는 `action`, 증축분은 `accent`.
- 보고서(`/report`): **모션 없음.** A4 종이, 제목은 같은 산세리프 600, 숫자는 크게, 근거는 뒤로. 인쇄(`print:`) 스타일을 우선한다. 오른쪽 스티키 목차는 인쇄 시 숨김.

## 5. "건축주가 검토에 참여한다"는 인상을 만드는 장치

| 장치 | 구현 아이디어 |
|---|---|
| 직접 조정 | 가정값 패널(슬라이더·숫자 입력)을 화면 중심에 두고, 값을 바꾸면 결과·3D·ROI가 즉시 변경 |
| 내 입력 표시 | 건축주가 바꾼 값에는 파란 점과 "내 가정값" 라벨, [기본값으로] 되돌리기 버튼 |
| 결정 포인트 | 단계마다 "건축주께서 정하실 것" 박스 1개 |
| 함께 보기 | 보수/기준/낙관 3개 시나리오 비교, 완화 전/후 토글 |
| 말투 | "함께 검토합니다" 같은 협업형 문장. 과장·단정 표현 금지 |
| 보고서 | 표지에 "건축주 입력 조건" 요약 |

현재 분석 화면에는 가정값 입력 패널이 없다(시나리오 선택만 가능). 위 장치는 기능 추가가 필요하다.

### 신뢰 장치
법규 근거 문구, 출처, "예시 가정값" 라벨, 면책 문구, 보수 시나리오·리스크 병기. 좋은 숫자만 강조하지 않는다.

## 6. 모션 가이드

| 효과 | 사양 |
|---|---|
| 기본 이징·길이 | `cubic-bezier(0.2, 0.7, 0.2, 1)`, 400~700ms |
| 텍스트·타일 등장 | 아래→위 페이드, 섹션당 1회만 (반복 재생 금지) |

| 금지 | 보고서·인쇄 화면의 모션, 자동 재생 소리, 과한 패럴랙스 |

## 8. Claude Code에 요청할 때 (순서 권장)

각 단계는 "먼저 계획만 보여주고 내가 승인하면 작업해" 방식으로, 단계마다 `npm run dev`로 확인하고 커밋한다.

1. **토큰·폰트**: 1·2장 기준으로 `globals.css`의 색·폰트 스택·크기 스케일을 적용한다. (완료)
2. **상단 바·히어로·주소 입력**: 4-1의 ①②. (완료)
3. **타일 블록 4개 + 샘플 사례 타일 + 푸터**: 4-1의 ③④⑤. 문구는 초안을 먼저 확인받는다.
4. **분석·보고서 톤 정리**: 선택=파랑, 증축분=주황 규칙 점검, 인쇄 미리보기로 쪽 나눔 재검토.
5. **참여 장치**: 5장 기준으로 가정값 패널 구현 (별도 기능 계획 필요).
