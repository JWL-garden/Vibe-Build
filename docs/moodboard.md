## 0. 한 줄 콘셉트

**"건축주와 함께 검토하는, 투명한 증축 타당성 리포트"**

- 키워드: 간결 · 정돈 · 신뢰 · 큰 타이포 · 투명한 근거
- 방문자: 건물주(주 사용자), 건설사·건축사(검토자)
- 레퍼런스: **apple.com 한국 홈페이지** — 흰색·옅은 회색 구획, 큰 헤드라인 + 한 줄 설명 + 버튼, 둥근 타일
- 따라 하는 것은 색·글자·레이아웃의 "방식"이다. **애플의 이미지·제품 사진·문구·로고는 쓰지 않는다.** 문구는 같은 호흡(짧은 헤드라인 + 한 줄 설명 + 버튼)만 참고해 새로 쓴다.

### 디자인 원칙 3가지
1. **흰색과 회색, 그리고 파랑 하나.** 바탕은 흰색과 `#f5f5f7`을 번갈아 쓰고, 색은 파랑 계열로 "건축주가 누르고 고르는 곳"과 "증축·재건축분"을 알린다. 그 밖의 강조색은 두지 않는다.
2. **파랑 = 누를 수 있는 것, 회색 = 이미 정해진 것.** 입력·선택·버튼·링크는 파랑이고, 기존 건물·법규 기준·계산 결과·출처는 회색·잉크색이다.
3. **모든 숫자에는 근거 표기가 붙는다.** "예시 가정값", "샘플 데이터", 법규 근거, 면책 문구를 숨기지 않는다.

> **주황 폐지 (2026-10-14):** 이전 무드보드(v1)의 주황 `#E0621B`와 Deep Slate 보조색은 쓰지 않는다. 웹페이지에서 주황색은 모두 삭제했다.

| 역할 | 토큰 | HEX | 사용처 |
|---|---|---|---|
| 글자 | `ink` | `#1d1d1f` | 제목, 본문 |
| 보조 글자 | `ink-soft` | `#6e6e73` | 설명, 표 보조 (12px 이하 본문에는 이 색) |
| 약한 글자 | `ink-faint` | `#86868b` | 캡션, 출처, 비활성 |

| **행동·참여** | `action` | `#0071e3` | CTA 버튼, 입력·선택, "내 가정값" 점, **3D 재건축분** |

| 기존·보조 | `existing` | `#8d9494` | 3D 기존 건물, 비활성 도형 |

**비율 가이드:** 흰색 55% / 옅은 회색 25% / Ink 12% / 회색 5% / 파랑 3%

### 3D 색 규칙
| 요소 | 색 |
|---|---|
| 기존 건물 | 회색 `#a9a9a9` (UI 토큰 `existing`) |
| **증축분** | **`#0066CC`** |
| **재건축분(신축 매스)** | **`#0071E3`** |
| 주변 건물 | 흰색·옅은 회색 (반투명) |
| 일조 사선면 | 반투명 (파랑 계열, 불투명도 낮게) |

증축과 재건축은 한 화면에서 함께 쓰지 않는다(시나리오마다 하나). 같은 파랑 계열이라 범례로 구분한다.

### 접근성
- `#0071e3`와 흰색의 명암비는 약 4.7:1이라 작은 글자에도 쓸 수 있다.
- `#86868b`는 약 3.5:1이라 12px 이하 본문에는 `#6e6e73`을 쓴다.
- 그라디언트·네온 색·과한 그림자는 쓰지 않는다. 색 구획은 `mist` 배경과 `line` 선으로 나눈다.

### 이전 무드보드(v1)와 달라진 점
- 주황 포인트 → 파랑 포인트 (증축분 `#0066CC`, 재건축분 `#0071E3`)
- Deep Slate 보조색 → 삭제 (표 머리글용 `deep`만 중립 회색으로 유지)
- 따뜻한 Mist `#F6F6F4` → 차가운 `#F5F5F7`
- 세리프 제목 → 산세리프 한 가지

## 3. 텍스트

제목과 본문 모두 산세리프 한 가지로 통일하고, 굵기(600)와 크기 차이로 위계를 만든다.

| 요소 | 토큰 | 크기 | 굵기 | 행간 | 자간 |
|---|---|---|---|---|---|
| Hero | `text-display` | 44–96px (제안 56px) | 600 | 1.05 | −0.025em |
| Headline | `text-h2` | 32–56px | 600 | 1.07 | −0.015em |
| Tile 제목 | `text-h3` | 28–40px | 600 | 1.14 | −0.01em |
| Subhead | – | 21–28px | 400 | 1.2–1.38 | −0.01em |
| 본문 (측정값) | `text-body` | 17px | 400 | 1.47 | −0.022em |
| 캡션·면책 | `text-caption` | 12px | 400 | 1.5 | −0.01em |
| KPI 숫자 | `text-kpi` | 44–72px | 600, `tabular-nums` | 1.0–1.1 | −0.025em |

### 글꼴 구성
```
-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", Pretendard, "Malgun Gothic", system-ui, sans-serif
```
SF Pro는 애플 기기에서만 표시되고 웹에 직접 배포할 수 없는 서체라서, 그 밖의 환경에서는 Pretendard 가변 폰트(`app/fonts`, OFL)가 대신 표시된다.

공통 규칙: 국문은 `word-break: keep-all`, 숫자는 `font-variant-numeric: tabular-nums`.

### 문구 호흡
- 헤드라인은 한 문장, 짧게. 그 아래 한 줄 설명, 그 아래 버튼 두 개.
- "분석 시작하기"(파란 버튼)와 "샘플 보고서 보기 ›"(파란 글자 링크)처럼 동사로 끝나는 짧은 라벨.
- 과장·단정 표현은 쓰지 않는다. "함께 검토합니다" 같은 협업형 문장.

**보고서(A4) 주의:** 글꼴·크기를 바꾸면 쪽 나눔이 달라진다(`ReportPage`, `lib/report/paginate.ts`). 디자인 확정 후 인쇄 미리보기로 쪽 나눔을 재검토한다.

## 4. 레이아웃 — 타일을 쌓는 구성

전체 폭 구획을 흰색과 `#f5f5f7`로 교대하고, 그 안에 큼직한 둥근 타일을 넣는다. 타일마다 제목, 한 줄 설명, 링크 두 개, 그림 하나만 둔다.

| 항목 | 값 |
|---|---|
| 타일 모서리 | 28px (카드는 18px, `--radius-card`) |
| 타일 간격 | 14px |
| 섹션 위아래 여백 | 100px 이상 |
| 콘텐츠 폭 | 1024~1080px (주소 입력칸 680px) |
| 상단 바 | 높이 48px, 흰색 80% 투명 + 배경 블러(`backdrop-saturate-150`), 서비스 이름 + 오른쪽 작은 메뉴 |

### 4-1. 랜딩 흐름 (`app/page.tsx`)
1. 반투명 내비 + 큰 헤드라인 + **주소 입력**(누르면 T1·T2 주소 목록) — 메인에서는 헤더의 "주소 검색" 버튼을 두지 않는다
2. 3D 증축 시뮬레이션 (회색 + 파랑)
3. 타일 2~3개: 일조 / 용적률 / 가정값
4. 샘플 보고서 미리보기 타일 (전체 폭)
5. 검토 과정 4단계, 면책, 푸터

### 4-2. 분석·보고서 화면
- 분석 화면: 스텝퍼 / 내용 / 3D 미니뷰 구성 유지. 카드는 흰색 바탕 위 `#f5f5f7`, 모서리 18px.
- 보고서(`/report`): **모션 없음.** A4 흰 바탕, 인쇄 우선. 제목은 같은 산세리프 600, 숫자는 크게, 근거는 뒤로. 오른쪽 스티키 목차는 인쇄 시 숨김.

## 5. 구성요소 — 건축주가 직접 만지는 부분

| 구성요소 | 규칙 |
|---|---|
| 기본 버튼 | 파란 pill(`action`), 17px 기본·14px 작은 버튼, 호버 `#0077ed` |
| 보조 버튼 | 외곽선 pill (`link` 색 테두리), 호버 시 채움 |
| 링크 | 파란 글자(`link`) + `›`, 호버 시 밑줄 |
| 입력창 | 테두리 `#d2d2d7`, 모서리 12px, 선택하면 파란 외곽 링 |
| 슬라이더·선택 | 파랑. 바꾼 값에는 파란 점 + "내 가정값" 라벨, [기본값으로] 되돌리기 |
| 결정 포인트 | "건축주께서 정하실 것" 박스 1개 (파란 점) |
| 시나리오 비교 | 보수/기준/낙관 3분할(seg) 탭, 완화 전/후 토글 |
| 계산 결과 | 잉크색 큰 숫자(KPI), 라벨은 회색. 파랑으로 칠하지 않는다 |
| 배지 | `예시 가정값`, `샘플 데이터` (회색 pill), 선택·강조는 연한 파랑 pill |

> 현재 분석 화면에는 가정값 입력 패널이 없다(시나리오 선택만 가능). "내 가정값"·결정 포인트는 기능 추가가 필요하다.

### 신뢰 장치
법규 근거 문구, 출처, "예시 가정값" 라벨, 면책 문구, 보수 시나리오·리스크 병기. 좋은 숫자만 강조하지 않는다.

## 6. 이미지

배경은 흰색이나 `#f5f5f7` 한 가지, 피사체는 하나, 그림자는 아주 부드럽게. 3D 매스는 회색과 파랑 계열 색만 쓴다.

| 이미지 | 규칙 |
|---|---|
| 3D 매스 | 기존=회색, 증축=`#0066CC`(재건축=`#0071E3`), 주변=흰색·옅은 회색 |
| 단면·선화 | 가는 선, 치수선, 파란 사선면 |
| 전·후 비교 | 같은 각도, 같은 배경, 증축분만 파랑 |

**이렇게:** 흰색·옅은 회색 배경에 건물 하나와 넉넉한 여백. 자체 3D 캡처를 히어로·보고서 표지에 사용. 사진은 흐린 날 자연광, 낮은 채도. 샘플 건물·수치에는 "샘플 데이터" 표기.

**하지 않기:** 그라디언트 배경, 네온 색, 과한 그림자. 한 화면에 파랑 계열 외의 강조색 추가. 애플의 이미지·제품 사진·문구 사용. 가짜 후기·고객사 로고·실적 수치.

## 7. 모션

스크롤하면 요소가 살짝 위로 떠오르며 나타난다. 한 번만 재생하고 보고서·인쇄 화면에는 쓰지 않는다.

| 효과 | 사양 |
|---|---|
| 기본 이징 | `cubic-bezier(.28, .11, .32, 1)`, 700~1000ms |
| 등장 | 아래에서 24~28px 떠오르며 페이드, 줄 간 120ms 지연 |
| 숫자 | 화면에 들어올 때 1회 카운트업, 약 1.2초 |
| 내비게이션 | 스크롤해도 상단 고정, 반투명 블러 48px |
| 카드 | 마우스를 올리면 4px 상승 |
| 접근성 | `prefers-reduced-motion`이면 모든 모션 제거 (전역 CSS 적용됨) |
| 금지 | 보고서·인쇄 화면 모션, 반복 재생, 자동 재생 소리 |

## 9. Claude Code에 요청할 때 (순서 권장)

각 단계는 "먼저 계획만 보여주고 내가 승인하면 작업해" 방식으로, 단계마다 `npm run dev`로 확인하고 커밋한다.

1. **토큰·폰트**: 2·3장 기준 `globals.css` 색·폰트 스택·크기 스케일. (완료)
2. **주황 삭제 + 3D 색**: 증축 `#0066CC`, 재건축 `#0071E3`. (완료)
3. **상단 바·히어로·주소 입력**: 4-1의 ①. (완료)
