   - 원본 시트 2개 (`토지임야목록_원본`, `개별공시지가_원본`)
3. **토지가액 계산 시 대지면적 주의** — 토지대장 면적 ≠ 건축물대장 대지면적

## 1단계. 기준 데이터 관리 체계 만들기 (최초 1회)

엑셀 교체 전에 먼저 해 두면 이후 교체가 쉬워진다.

### [D-1] 계획만

```
기준 데이터(엑셀 등)가 앞으로 계속 바뀌고 시트도 늘어날 예정이야. 관리 체계를 만들려고 해.
코드는 고치지 말고 계획만 보여줘.

목표:
1) 기준 데이터 파일 경로·버전을 lib/data/source.json 한 곳에서만 관리
   예: { "excelPath": "../261007_....xlsx", "version": "261007-a", "note": "변경 요약" }
2) "시트 → JSON" 매핑을 lib/data/sheetMap.json으로 데이터화
   (시트명, 출력 JSON 파일명, 사용할 컬럼, 키 컬럼=PNU, 용도 설명, 사용 여부)
   → 앞으로 시트가 추가되면 이 파일에 한 줄만 추가하면 되게
3) 변환된 JSON마다 meta(원본 파일명, version, 변환 일시, 시트명, 행 수) 포함
4) docs/data-changelog.md에 버전별 변경 이력(추가 시트, 바뀐 값, 영향받는 화면·보고서) 기록
5) npm run data:check: 필수 시트·컬럼 존재, PNU 중복, T1·T2 필수값 누락, 단위 이상값 검사

지금 scripts/build-excel-data.mjs와 lib/data 구조 기준으로 바꿀 파일 목록과 작업 순서를 표로 보여줘.
```

### [D-2] 구현

```
[D-1] 계획대로 구현해줘. 한 번에 하나씩:
① source.json + sheetMap.json → ② build-excel-data.mjs가 이 두 파일을 읽도록 수정
→ ③ JSON meta 추가 → ④ data:check 스크립트 → ⑤ data-changelog.md 첫 항목(현재 버전 261007 비고4 적용) 작성.
끝날 때마다 무엇을 확인하면 되는지 알려줘.
```

### [D-3] 규칙 문서 반영

```
CLAUDE.md의 "기준 엑셀이 정답" 규칙에서 파일명을 빼고
"lib/data/source.json에 지정된 기준 데이터가 정답, 변경 이력은 docs/data-changelog.md"로 바꾸고,
docs/design.md에 "13장. 기준 데이터 관리 규칙"(source.json, sheetMap.json, data:check, changelog, 교체 절차)을 추가해줘.
design.md 12-1의 파일명도 source.json을 가리키도록 바꿔. 수정안을 먼저 보여주고 승인 후 반영해.
```

## 3단계. 공시지가를 수익성 계산에 반영

### [L-1] 계획만

```
lib/data/landPrice.json의 개별공시지가를 보고서 수익성 계산에 쓰려고 해. 계획만 보여줘.

조건:
- 토지가액은 시세가 아니라 "공시지가 기준"임을 화면·보고서에 반드시 표기 (기준연월, 공시일 포함)
- 대지면적 주의: 건축물대장 대지면적과 토지대장 면적이 다르다
  (T1 200.07 vs 93㎡ 외필지 1 / T2 373.1 vs 255㎡ 외필지 3)
  → 토지가액 = Σ(구성 필지 면적 × 각 필지 공시지가)를 원칙으로 하고,
    외필지 데이터가 없으면 "대표 필지 공시지가 × 건축물대장 대지면적 (추정)"으로 계산해서 "추정" 배지 표시
- 값은 types → lib/rules/financeDefaults(사용 방식 설정) → lib/calc/finance.ts 순서로 반영, 화면에서 재계산 금지

수익성에 어떻게 쓸지 아래 후보별로 설계서 5-4 수식 수정안을 보여줘:
 a) 1장 현황: 토지가액(공시지가 기준) 표시
 b) 5장 수익: 증축 전·후 자산가치 = 토지가액 + 건물가치, 토지 포함 총투자 대비 수익률
 c) 4장 사업비: 토지 담보 대출 한도(LTV 가정값) 참고 표시
 d) 보유세 등 세금 참고값 (하면 "세무사 확인 필요" 표기)
T1·T2의 손계산 예시도 함께 보여줘.
```

### [L-2] 구현

```
[L-1]에서 내가 승인한 항목만 구현해줘.
finance.ts 수정 + Vitest 테스트(T1·T2 토지가액 손계산값 일치)를 추가하고,
design.md 4-4 수익성 데이터 표와 5-4 수식에 공시지가 항목을 반영해.
```

### [L-3] 화면·보고서 반영

```
공시지가 결과를 화면 ⑧ 수익성, 보고서 1장(현황)·5장(수익)·부록(데이터 출처: 개별공시지가_2단계, 기준연월)에 반영해줘.
한 곳씩 진행하고 npm run dev로 확인할 위치를 알려줘. 끝나면 T1·T2 보고서 숫자를 점검해.
```

## 4단계. 다음 교체부터 쓰는 반복 루틴

Claude Code의 커스텀 명령(`.claude/commands/`)으로 만들어 두면 `/명령이름` 한 줄로 실행된다.

### [D-4] 데이터 교체 명령 만들기

```
.claude/commands/data-update.md 커스텀 명령을 만들어줘.
사용법: /data-update <새 파일명> <변경 요약>
실행 순서:
1) 새 파일과 현재 source.json 파일의 시트·컬럼·값 비교표 출력 (코드 수정 전 멈추고 승인 요청)
2) 승인 후 source.json 갱신(version 증가), 새 시트는 sheetMap.json에 추가 제안
3) npm run data:excel → data:check → npm test
4) T1·T2 값 변화와 영향받는 화면·보고서 장 목록 보고
5) design.md 12-2·12-3 기대값 수정이 필요하면 수정안 제시
6) data-changelog.md 기록 후 커밋 제안
```

### 이후 사용 예

```
/data-update "261020_데이터 통합_○○ 추가.xlsx" "○○ 시트 추가"
```

- 이전 버전 엑셀은 삭제하지 말고 `##old` 폴더에 날짜 파일명 그대로 보관한다 (버전 비교용).
